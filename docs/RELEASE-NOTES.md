# Marketing Academy2.4.0 — secure backup recovery and Unicode authentication

Adds Arabic forgotten-password recovery to a new independent account from an encrypted `.academy` backup and its protection phrase. Original account/password/data remain intact; wrong phrases, duplicate names and invalid state are rejected. New account creation and learning-state restore are transactional. Without the password or a usable backup+phrase, encrypted data cannot be recovered. No email reset or cloud sync.

Fixes two reproduced compatibility defects: valid Arabic names with combining marks were rejected; valid long Unicode passwords accepted by the engine were clipped by HTML input limits. Shared validation now follows Unicode codepoint limits while password bytes, hashes, existing identities, database schema1 and Production/QA paths remain unchanged. Three previously verified session/capacity/backoff corrections remain covered.

Automated release gates require70 unit/integration tests on Linux/Windows,27 browser paths, Docker durability, actual both old2.3.1 EXEs reproducing the Unicode issues, and both corrected EXEs passing recovery/password-change/restart/offline/account-isolation/migration and concurrent Production/QA isolation. verification.json reports the actual same-source results; a source build alone is not Windows execution proof.

Download Production for normal use; QA has a separate immutable profile. Both bundle runtime/SQLite/curriculum and require no Node.js, Python, Docker or running backend. See START_AR.md. Both EXEs are unsigned; Windows SmartScreen/organization policies may warn. Windows Actions does not represent every clean physical PC or manual Explorer test. This is a working preview; independent educational review and learner validation remain open, and simulated campaigns are not real performance. Earlier releases remain intact.
