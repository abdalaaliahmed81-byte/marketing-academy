# Accounts, persistence and recovery

Arabic registration/login are available on first launch. Use a12–128 character passphrase. Settings provides display-name editing, password changes and study-profile controls; login name remains stable. “تبديل المستخدم” locks and logs out before another user's login. Each new login opens only that account's lessons, notes, attempts, practice submissions, missions, study history, module projects and portfolio. No account list is exposed to unauthenticated users.

Desktop uses its packaged main-process SQLite engine with no HTTP listener. It requires neither Docker nor installed Node/server. Passwords use salted PBKDF2-SHA256600000; data keys are wrapped separately and records encrypted/authenticated per owner. Renderer receives no password verifier/session token/key. SQLite schema identity/migrations, foreign keys, WAL/FULL, revision checks and atomic transactions protect consistent writes. Corrupt/foreign/future schemas fail without resetting data. Existing IDB→SQLite migration leaves the source intact.

The optional Compose edition runs nginx web + Node API, both non-root, read-only roots, dropped capabilities, no-new-privileges and health checks. API storage is the persistent academy_data volume. Default port8080 binds loopback; compose.env.example lists overrides. Remote origin requires HTTPS with trusted TLS termination. Do not use down --volumes on a deployment whose data must survive. Sessions are HttpOnly SameSiteStrict cookies, Secure for HTTPS,30min protected-request idle and12h absolute. Restart invalidates sessions and requires login but preserves account/progress data. No Redis or external database is required.

An owner-scoped five-minute heartbeat while recently active prevents long editing from expiring the server idle lease; it never extends the12h limit. UI also locks after30min without input/scroll and12h maximum. Logout waits for its acknowledgement before permitting a new login; request timeout prevents an unreachable server from hanging switching indefinitely. If the server cannot be reached, the UI discloses failure to revoke the remote session and clears local learning memory. Browser scheduling/OS compromise are not hard real-time or device-administrator security guarantees.

There is **no automatic cloud synchronization**. Desktop, each Docker deployment and legacy browser-local PWA are separate stores. Export a passphrase-encrypted progress backup, privately transfer it, and import into the authenticated target account. The importer validates IDs, schema/versions, duplicates, score/completion rules and size before one atomic replacement. Invalid backups preserve existing progress. Passwords, login/profile identity and session keys are excluded. Import replaces only target-account learning data; it is not an account credential restore or a merge/sync service. Keep the original backup and test recovery before deleting any device data.

Validation evidence is maintained in AI_PROGRESS.md and QA.md; historical Windows/CI evidence must never be relabeled as a later build. No full curriculum approval is implied by completing the account architecture.
